# ДЗ №3 Servlet API и AOP

## Требования

- Все взаимодействие должно теперь осуществляться через отправку HTTP запросов.
- Сервлеты должны принимать JSON и отдавать также JSON.
- Для сериализации и десериализации использовать Jackson.
- Использовать понятное именование эндпоинтов.
- Возвращать разные статус-коды.
- Добавить DTO (если ранее не было заложено в логике).
- Для маппинга сущностей в DTO использовать MapStruct.
- Реализовать валидацию входящих DTO.
- Сделать аудит действий пользователя через аспекты.
- Также реализовать на аспектах логирование выполнения любого метода (с замером времени выполнения).
- Сервлеты должны быть покрыты тестами.

## Выполненные задачи

1. **Взаимодействие через отправку HTTP запросов:**
  - Все взаимодействие осуществляется через HTTP запросы с использованием сервлетов.

2. **Сервлеты принимают и отдают JSON:**
  - Реализованы сервлеты, которые принимают запросы в формате JSON и возвращают ответы в формате JSON с использованием Jackson.

3. **Использование Jackson для сериализации и десериализации:**
  - Все сервлеты используют библиотеку Jackson для преобразования объектов в JSON и обратно.

4. **Понятное именование эндпоинтов:**
  - Использованы понятные и логичные URL для эндпоинтов сервлетов.

5. **Возвращение разных статус-кодов:**
  - В зависимости от результатов обработки запросов возвращаются соответствующие HTTP статус-коды.

6. **Добавлены DTO:**
  - Созданы DTO для всех сущностей (`User`, `Workspace`, `ConferenceRoom`, `Booking`) для передачи данных между клиентом и сервером.

7. **Маппинг сущностей в DTO с использованием MapStruct:**
  - Реализован маппинг сущностей в DTO и обратно с использованием MapStruct.

8. **Реализована валидация входящих DTO:**
  - Используется аннотация `@Valid` для валидации входящих данных в DTO с использованием Bean Validation API.

9. **Аудит действий пользователя через аспекты:**
  - Реализован аспект для аудита действий пользователя, который логирует все действия пользователей.

10. **Логирование выполнения методов через аспекты:**
  - Реализован аспект для логирования выполнения методов с замером времени выполнения.

11. **Покрытие сервлетов тестами:**
  - Реализованы тесты для всех сервлетов, использующие Mockito и JUnit для обеспечения корректности работы.

### Требования и пояснение к реализации

- **Все взаимодействие должно теперь осуществляться через отправку HTTP запросов:**  
  Приложение использует сервлеты для обработки всех HTTP запросов.

- **Сервлеты должны принимать JSON и отдавать также JSON:**  
  Все сервлеты принимают запросы в формате JSON и возвращают ответы в формате JSON. Для этого используется Jackson.

- **Для сериализации и десериализации использовать Jackson:**  
  Библиотека Jackson используется для сериализации и десериализации объектов в JSON и из JSON.

- **Использовать понятное именование эндпоинтов:**  
  Все URL эндпоинтов сервлетов понятны и логичны, что облегчает использование API.

- **Возвращать разные статус-коды:**  
  В зависимости от результата обработки запроса возвращаются соответствующие HTTP статус-коды (например, 200 OK, 201 Created, 400 Bad Request, 404 Not Found, 500 Internal Server Error).

- **Добавить DTO:**  
  Созданы DTO классы для передачи данных между клиентом и сервером.

- **Для маппинга сущностей в DTO использовать MapStruct:**  
  MapStruct используется для автоматического маппинга между сущностями и DTO.

- **Реализовать валидацию входящих DTO:**  
  Используется Bean Validation API для валидации входящих данных в DTO.

- **Сделать аудит действий пользователя через аспекты:**  
  Реализован аспект, который логирует действия пользователя и сохраняет их в лог-файл.

- **Также реализовать на аспектах логирование выполнения любого метода (с замером времени выполнения):**  
  Реализован аспект, который логирует выполнение методов и измеряет время их выполнения.

- **Сервлеты должны быть покрыты тестами:**  
  Реализованы тесты для всех сервлетов с использованием JUnit и Mockito для проверки корректности их работы.

## Заключение

Приложение успешно обновлено в соответствии с требованиями и ограничениями. Реализовано управление коворкинг-пространством с использованием сервлетов, DTO, валидации, аспектов и логирования. Все требования задания выполнены, и приложение покрыто тестами для обеспечения его корректной работы.
